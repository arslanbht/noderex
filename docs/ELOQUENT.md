# Eloquent ORM

## Introduction

The Eloquent ORM included with NodeRex provides a beautiful, simple ActiveRecord implementation for working with your database. Each database table has a corresponding "Model" that is used to interact with that table. Models allow you to query for data in your tables, as well as insert new records into the table.

Before getting started, be sure to configure a database connection in your `src/config/database.ts` configuration file.

## Getting Started

### Defining Models

To get started, let's create an Eloquent model. Models typically live in the `src/app/Models` directory, but you are free to place them anywhere that can be auto-loaded according to your `tsconfig.json`.

#### Generating Model Classes

The easiest way to create a model instance is using the `make:model` Artisan command:

```bash
npm run artisan make:model User
```

If you would like to generate a database migration when you generate the model, you may use the `--migration` or `-m` option:

```bash
npm run artisan make:model User --migration
```

#### Eloquent Model Conventions

Models generated by the `make:model` command will be placed in the `src/app/Models` directory. Let's examine a basic model class:

```typescript
import { Entity, Column } from 'typeorm';
import { Model } from 'noderex';

@Entity('users')
export class User extends Model {
  @Column()
  name!: string;

  @Column()
  email!: string;
}
```

### Model Conventions

#### Table Names

By default, Eloquent will assume the User model stores records in the `users` table. You may specify a custom table by defining a `tableName` property on your model:

```typescript
@Entity('my_users')
export class User extends Model {
  // ...
}
```

#### Primary Keys

Eloquent will also assume that each model's corresponding database table has a primary key column named `id`. If necessary, you may define a protected `$primaryKey` property to specify a different column that serves as your model's primary key.

#### Timestamps

By default, Eloquent expects `created_at` and `updated_at` columns to exist on your model's corresponding database table. Eloquent will automatically set these column's values when models are created or updated. If you do not want these columns to be automatically managed by Eloquent, you should remove the `@CreateDateColumn()` and `@UpdateDateColumn()` decorators from your model.

## Retrieving Models

### Collections

As we have seen, Eloquent methods like `find` return instances of the model. However, when retrieving multiple records, Eloquent returns a collection of models:

```typescript
const users = await User.find();
// users is an array of User instances
```

### Chunking Results

If you need to process thousands of Eloquent records, use the `chunk` method. The `chunk` method will retrieve a subset of Eloquent models at a time, feeding them to a given closure for processing:

```typescript
await User.find().then(users => {
  // Process users in chunks
  for (let i = 0; i < users.length; i += 100) {
    const chunk = users.slice(i, i + 100);
    // Process chunk
  }
});
```

### Retrieving Single Models / Aggregates

In addition to retrieving all of the records matching a given query, you may also retrieve single records using `find` or `findOne`:

```typescript
// Retrieve a model by its primary key
const user = await User.findOne({ where: { id: 1 } });

// Retrieve the first model matching the query constraints
const user = await User.findOne({ where: { email: 'john@example.com' } });
```

#### Not Found Exceptions

Sometimes you may wish to throw an exception if a model is not found. This is particularly useful in routes or controllers. The `findOrFail` method will retrieve the first result of the query; however, if no result is found, an exception will be thrown:

```typescript
const user = await User.findOne({ where: { id: 1 } });
if (!user) {
  throw new NotFoundError('User not found');
}
```

## Inserting & Updating Models

### Inserts

Of course, when using Eloquent, we don't only need to retrieve models from the database. We also need to insert new records. Thankfully, Eloquent makes it simple. To insert a new record into the database, you should instantiate a new model instance and set attributes on the instance, then call the `save` method:

```typescript
const user = new User();
user.name = 'John Doe';
user.email = 'john@example.com';
await user.save();
```

Alternatively, you may use the `create` method to "save" a new model using a single statement:

```typescript
const user = await User.create({
  name: 'John Doe',
  email: 'john@example.com',
});
```

#### Mass Assignment

You may also use the `fill` method to fill the model with an array of attributes:

```typescript
const user = new User();
user.fill({
  name: 'John Doe',
  email: 'john@example.com',
});
await user.save();
```

### Updates

The `save` method may also be used to update models that already exist in the database. To update a model, you should retrieve it, set any attributes you wish to update, and then call the `save` method:

```typescript
const user = await User.findOne({ where: { id: 1 } });
user.name = 'Jane Doe';
await user.save();
```

#### Mass Updates

Updates can also be performed against models that match a given query. In this example, all flights that are `active` and have a `destination` of `San Diego` will be marked as delayed:

```typescript
await User.update(
  { active: true },
  { name: 'John Doe' }
);
```

### Deleting Models

To delete a model, you may call the `remove` method on the model instance:

```typescript
const user = await User.findOne({ where: { id: 1 } });
await user.remove();
```

#### Deleting Models By Query

Of course, you may delete models without retrieving them first. To do so, call the `delete` method on a query:

```typescript
await User.delete({ where: { active: false } });
```

## Relationships

### Introduction

Database tables are often related to one another. For example, a blog post may have many comments, or an order could be related to the user who placed it. Eloquent makes managing and working with these relationships easy.

### Defining Relationships

#### One To Many

A one-to-many relationship is used to define relationships where a single model owns any amount of other models. For example, a blog post may have an infinite number of comments. Like all other Eloquent relationships, one-to-many relationships are defined by defining a method on your Eloquent model:

```typescript
import { Post } from './Post';

export class User extends Model {
  public posts() {
    return this.hasMany(Post, 'user_id');
  }
}
```

Once the relationship is defined, we can retrieve the related records using Eloquent's dynamic relationship properties. Since relationships also serve as query builders, you may add further constraints to the relationship query:

```typescript
const user = await User.findOne({ where: { id: 1 } });
const posts = await user.posts().get();
```

#### Belongs To

A "belongs to" relationship is the inverse of a "has many" relationship. To define this relationship, we will place a `belongsTo` method on the child model:

```typescript
import { User } from './User';

export class Post extends Model {
  @Column()
  user_id!: number;

  public user() {
    return this.belongsTo(User, 'user_id');
  }
}
```

Once the relationship is defined, we can retrieve the related model:

```typescript
const post = await Post.findOne({ where: { id: 1 } });
const user = await post.user().get();
```

#### Has One

A "has one" relationship is similar to a "has many" relationship; however, the relationship will only return one related model instead of multiple:

```typescript
export class User extends Model {
  public phone() {
    return this.hasOne(Phone, 'user_id');
  }
}
```

#### Many To Many

Many-to-many relationships are slightly more complicated than `hasOne` and `hasMany` relationships. An example of a many-to-many relationship is a user that has many roles and those roles are also shared by other users:

```typescript
export class User extends Model {
  public roles() {
    return this.belongsToMany(Role, 'role_user', 'user_id', 'role_id');
  }
}
```

### Polymorphic Relationships

#### Polymorphic One To One

A polymorphic relationship allows the child model to belong to more than one type of model using a single association. For example, imagine you are building an application that allows users to share blog posts and videos. In such an application, a `Comment` model might belong to both the `Post` and `Video` models.

#### Morph One

A "morph one" relationship is similar to a typical one-to-one relationship; however, the child model can belong to more than one type of model using a single association:

```typescript
export class Post extends Model {
  public image() {
    return this.morphOne(Image, 'imageable_type', 'imageable_id');
  }
}
```

#### Morph Many

A "morph many" relationship is similar to a typical one-to-many relationship; however, the child model can belong to more than one type of model using a single association:

```typescript
export class Post extends Model {
  public comments() {
    return this.morphMany(Comment, 'commentable_type', 'commentable_id');
  }
}
```

#### Morph To

The inverse of `morphOne` and `morphMany` relationships is the `morphTo` relationship. This relationship allows the polymorphic child model to easily retrieve its parent model:

```typescript
export class Comment extends Model {
  public commentable() {
    return this.morphTo<Post | Video>(
      'commentable_type',
      'commentable_id',
      { Post: Post, Video: Video }
    );
  }
}
```

#### Polymorphic Many To Many

A "polymorphic many-to-many" relationship is similar to a typical many-to-many relationship; however, the child model can belong to more than one type of model using a single association. For example, blog posts and videos could share a polymorphic relationship to a `Tag` model:

```typescript
export class Post extends Model {
  public tags() {
    return this.morphToMany(Tag, 'taggables', 'taggable_type', 'taggable_id');
  }
}
```

## Query Scopes

### Introduction

Scopes allow you to encapsulate query constraints in reusable methods. To define a scope, prefix an Eloquent model method with `scope`:

```typescript
export class User extends Model {
  public static scopePopular(query: any) {
    return query.where('votes', '>', 100);
  }

  public static scopeActive(query: any) {
    return query.where('active', 1);
  }
}
```

### Utilizing Query Scopes

Once a scope has been defined, you may call the scope methods when querying the model. However, you should not include the `scope` prefix when calling the method:

```typescript
const users = await User.scope('popular').find();
```

You may even chain multiple scopes together:

```typescript
const users = await User.scope('popular').scope('active').find();
```

### Global Scopes

Global scopes allow you to add constraints to all queries for a given model. NodeRex's own "soft delete" functionality utilizes global scopes to only retrieve "non-deleted" models from the database. Writing your own global scopes can provide a convenient, easy way to make sure every query for a given model receives certain constraints.

#### Writing Global Scopes

To write a global scope, define a class that implements the scope interface. Then, register the scope using the model's `addGlobalScope` method:

```typescript
User.addGlobalScope('active', (query) => {
  return query.where('active', 1);
});
```

## Collections

### Introduction

All multi-result sets returned by Eloquent are instances of the `Array`, and provide a variety of helpful methods for working with your results.

### Available Methods

All collections extend the base Array, so they naturally inherit all of the powerful methods provided by JavaScript arrays. In addition, collections provide a variety of methods that are specifically designed for working with collections of Eloquent models.

Since all of NodeRex's collections implement JavaScript's array methods, you may use any of the array methods on your collections:

```typescript
const users = await User.find();
const activeUsers = users.filter(user => user.active);
const names = users.map(user => user.name);
```

## Mutators & Accessors

### Accessors & Mutators

#### Defining An Accessor

An accessor transforms an Eloquent attribute value when it is accessed. To define an accessor, create a `get{Attribute}Attribute` method on your model where `{Attribute}` is the "studly" cased name of the column you wish to access.

In this example, we'll define an accessor for the `first_name` attribute. The accessor will automatically be called by Eloquent when attempting to retrieve the value of the `first_name` attribute:

```typescript
export class User extends Model {
  @Column()
  first_name!: string;

  public getFirstNameAttribute(): string {
    return this.first_name.toUpperCase();
  }
}
```

#### Defining A Mutator

A mutator transforms an Eloquent attribute value when it is set. To define a mutator, define a `set{Attribute}Attribute` method on your model where `{Attribute}` is the "studly" cased name of the column you wish to access.

Let's define a mutator for the `first_name` attribute. This mutator will be automatically called when we attempt to set the value of the `first_name` attribute on the model:

```typescript
export class User extends Model {
  public setFirstNameAttribute(value: string): void {
    this.first_name = value.toLowerCase();
  }
}
```

## Serialization

### Introduction

When building APIs using NodeRex, you will often need to convert your models and relationships to arrays or JSON. Eloquent includes convenient methods for making these conversions, as well as controlling which attributes are included in the serialized representation of your models.

### Serializing To Arrays

To convert a model and its loaded relationships to an array, you should use the `toJSON` method:

```typescript
const user = await User.findOne({ where: { id: 1 } });
const array = user.toJSON();
```

### Hiding Attributes From Array / JSON Conversion

Sometimes you may wish to limit the attributes, such as passwords, that are included in your model's array or JSON representation. To do so, add a `toJSON` method to your model:

```typescript
export class User extends Model {
  public toJSON(): Record<string, any> {
    return this.hidden(['password', 'api_token']);
  }
}
```

Alternatively, you may use the `only` method to include only the specified attributes in the array representation of your model:

```typescript
const user = await User.findOne({ where: { id: 1 } });
const array = user.only(['id', 'name', 'email']);
```
